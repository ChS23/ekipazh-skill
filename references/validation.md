# Validation

Используй для проверки консистентности локальной базы бизнеса.

## Goal

Проверить, что профиль, анализ, правила, решения, контент и агенты не противоречат друг другу и достаточно полны для дальнейшей работы.

## Scope

Проверяй:

- `профиль/бизнес.md`
- `профиль/стиль.md`
- `профиль/состояние.md`
- `анализ/*.md`
- `анализ/персоны/*.md`
- `правила/*.md`
- `решения/*.md`
- `база/*.md`
- `агенты/*.md`
- `.agents/skills/*/SKILL.md`

## Checks

### Completeness

- профиль содержит продукт, клиента, ценность
- стиль содержит тон, обращение, запретные темы
- состояние содержит главную боль и текущие процессы
- правила имеют trigger, do, don't, good result
- агенты имеют входы, процесс и формат результата

### Consistency

- посты и КП соответствуют стилю
- правила не конфликтуют друг с другом
- персоны соответствуют клиентам из профиля
- решения не противоречат актуальным правилам
- мини-скиллы ссылаются на существующие локальные файлы

### Actionability

- каждый открытый вопрос понятен и привязан к области
- следующий шаг ясен
- нет “воды” вместо конкретики

## Output

Создай или обнови:

```text
база/validation-report.md
```

Формат:

```markdown
# Validation Report

**Дата:** YYYY-MM-DD
**Статус:** GO | NEEDS WORK | CRITICAL

## Summary

...

## Findings

| Severity | Area | Problem | Action |
| --- | --- | --- | --- |

## Action Items

- [ ] ...

## Next Step

...
```

## Verdict

- `GO`: нет critical, база пригодна для генерации и продаж.
- `NEEDS WORK`: есть пробелы, но можно работать.
- `CRITICAL`: профиль или стиль отсутствует, либо правила/агенты противоречат базовым фактам.
