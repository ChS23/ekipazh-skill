# Sales

Используй для КП, предложений, офферов, возражений и статусов сделок.

## Load Context

Прочитай:

- `профиль/стиль.md`
- `профиль/бизнес.md`
- `анализ/персоны/*.md`
- применимые `правила/*.md`
- `решения/*.md`
- последние КП и возражения из `контент/кп/**/*.md`, `контент/возражения/*.md`

## Proposal Flow

Когда пользователь просит КП или предложение:

Критические поля:

1. кто клиент
2. что клиенту нужно
3. какую проблему решаем
4. обращение: на ты или на вы

Вспомогательные:

1. бюджет или ожидания по цене
2. сроки
3. специфика клиента

Если неопределённость `> 0.1`, задай 1-3 вопроса. Если контекст ясен, генерируй.

Структура КП:

1. шапка
2. понимание задачи
3. решение
4. два тарифа
5. почему мы
6. следующий шаг
7. контакты

Не выдумывай цены. Если цены неизвестны, предложи диапазон или пометь `[уточнить]`.

Сохраняй по [proposal](assets/proposal.md) в:

```text
контент/кп/черновики/кп-клиент.md
```

Lifecycle:

- “отправил” → `отправлено/`, `status: отправлено`
- “принял” → `принято/`, `status: принято`
- “отказал” → `отказано/`, `status: отказано`, спросить причину

## Objection Flow

Когда пользователь приносит возражение:

Критические поля:

1. суть возражения
2. тип клиента
3. канал

Вспомогательные:

1. контекст до возражения
2. как обычно отвечает пользователь

Сначала дай краткий разбор:

```text
Возражение: ...
Тип: цена / доверие / срочность / конкуренты / непонимание ценности
Настоящая причина: ...
```

Потом 2 варианта ответа:

1. мягкий через понимание
2. прямой через факты

Сохраняй по [objection](assets/objection.md) в `контент/возражения/`.

Если возражение повторяется, предложи правило.
