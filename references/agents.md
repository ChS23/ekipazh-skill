# Agents And Mini-Skills

Используй, когда пользователь просит создать агента, автоматизировать процесс, работает с конкретным каналом или повторяет одну задачу регулярно.

## Important Boundary

Agent Skills standard не гарантирует, что каждый клиент поддерживает отдельные agent manifests. Поэтому Экипаж создаёт два переносимых слоя:

1. `агенты/агент-*.md` — role spec для будущих агентов и людей.
2. `.agents/skills/<name>/SKILL.md` — мини-скилл для skills-compatible клиентов, когда процесс зрелый.

Не создавай мини-скилл, если достаточно обычного правила.

## When To Create

Создавай локального агента/мини-скилл, если:

- пользователь явно просит “сделай агента”
- процесс повторяется 3+ раза
- есть правило, шаблон и стабильный вход/выход
- задача привязана к каналу: Telegram, Instagram, WhatsApp, КП, отзывы, публикации

## Agent Spec

Используй [agent](assets/agent.md). Сохраняй:

```text
агенты/агент-краткое-название.md
```

Агент должен содержать:

- миссию
- когда включается
- входные данные
- обязательный контекст
- процесс
- формат результата
- что не делать
- связанные правила и шаблоны

## Mini-Skill Spec

Если нужен настоящий skill для совместимых клиентов, создай:

```text
.agents/skills/<skill-name>/SKILL.md
```

Используй [mini-skill](assets/mini-skill.md).

Правила:

- `name` = имя папки, lowercase hyphen-case
- `description` описывает, когда использовать
- тело короткое: workflow, context files, output
- не копируй весь Экипаж
- ссылайся на локальные файлы бизнеса: `профиль/`, `правила/`, `база/`

## Build Process

1. Выясни повторяемую задачу.
2. Прочитай профиль, стиль, правила, последние примеры.
3. Извлеки стабильный процесс.
4. Создай agent spec.
5. Если процесс зрелый, создай mini-skill.
6. Предложи тест на реальном примере.

## Validation

Перед сохранением проверь:

- не дублирует ли новый агент существующий
- достаточно ли входных данных
- есть ли критерии хорошего результата
- нет ли конфликтов с правилами бизнеса
