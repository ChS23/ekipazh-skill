# Content

Используй для постов, идей, черновиков, публикации и редактирования контента.

## Preconditions

Если нет `профиль/стиль.md`, сначала проведи короткий onboarding. Не останавливайся сухой фразой; веди пользователя.

## Load Context

Прочитай:

- `профиль/стиль.md`
- `профиль/бизнес.md`
- `анализ/персоны/*.md`, если есть
- применимые `правила/*.md`
- `решения/*.md`
- последние 5 похожих файлов из `контент/посты/**/*.md`

Из истории извлеки: длину, зачины, CTA, ритм, эмодзи, частые темы.

## Repetition Check

Перед генерацией проверь, была ли похожая тема недавно.

Если была:

```text
Похоже, похожая тема уже была: [файл/дата].
Развиваем под другим углом или переключимся?
```

## Generate

Для поста создай 3 варианта:

1. экспертный
2. личный/сторителлинг
3. продающий/офферный

Каждый вариант должен:

- быть в стиле из `профиль/стиль.md`
- учитывать правила
- обращаться к боли персоны
- иметь CTA
- быть готовым к публикации

## Inline Edit

Если пользователь говорит:

- “короче” — сократи, сохрани смысл
- “длиннее” — добавь детали и примеры
- “смешнее/серьёзнее/мягче” — измени тон
- “убери эмодзи/добавь CTA” — локальная правка
- “вариант 2 + короче” — комбинируй

Правь последний вариант, не создавай новый процесс.

## Save

Когда пользователь выбирает вариант:

1. Создай `контент/посты/черновики/`, если нет.
2. Сохрани по [post](assets/post.md).
3. Добавь трассировку: стиль, бизнес, персона, правила, история.
4. Если пользователь говорит “опубликовал”, перемести в `контент/посты/опубликовано/` и обнови `status: опубликован`.

## Ideas

Если пользователь говорит “идея для поста”, не генерируй сразу. Сохрани в:

```text
контент/посты/идеи/YYYY-MM-DD-краткая-тема.md
```

Потом предложи превратить идею в черновик.

## Learning

Если пользователь повторяет одну и ту же правку 2-3 раза, предложи правило.

Если появляется регулярный контент-процесс для канала, предложи локального агента или мини-скилл.
