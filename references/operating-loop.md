# Operating Loop

Этот файл описывает, как Экипаж ведёт человека сам. Он применяется при старте, пустой папке, статусе проекта и любом длинном процессе.

## Empty Folder Bootstrap

Если рабочая папка пустая:

1. Если filesystem tools доступны, создай базовую структуру до основного интервью:

```bash
python3 <skill_dir>/scripts/bootstrap_workspace.py .
```

2. Если скрипт недоступен, создай вручную:

```text
профиль/
анализ/персоны/
правила/
контент/посты/идеи/
контент/посты/черновики/
контент/посты/опубликовано/
контент/кп/черновики/
контент/кп/отправлено/
контент/кп/принято/
контент/кп/отказано/
контент/возражения/
решения/
база/
агенты/
```

3. Начни onboarding. Если пользователь уже дал хоть какую-то информацию, сразу используй её.
4. Убедись, что есть черновики:
   - `профиль/бизнес.md`
   - `профиль/стиль.md`
   - `профиль/состояние.md`
   - `база/индекс.md`
   - `агенты/README.md`
   - `база/открытые-вопросы.md`
5. Не выдумывай факты. В черновиках ставь `[уточнить]`, но сохраняй даже неполные файлы как `status: черновик`.
6. Скажи пользователю, что папка заведена, покажи список созданных файлов и задай 2-3 самых важных вопроса.

## Session Start

Если папка не пустая:

1. Прочитай профиль и состояние.
2. Быстро оцени:
   - профиль есть?
   - анализ есть?
   - правила есть?
   - есть ли последние черновики?
   - есть ли открытые вопросы?
3. Верни короткий статус и один лучший следующий шаг.

Не пиши длинную диагностику, если пользователь просит конкретную задачу.

## Clarification Loop

Когда нужно собрать данные:

1. Раздели поля на критические и вспомогательные.
2. Считай неопределённость:

```text
Неопределённость = (незаполненных_крит / всего_крит) * 0.7
                 + (незаполненных_вспом / всего_вспом) * 0.3
```

3. Пока значение выше `0.1`, задавай 1-3 вопроса по самым важным пробелам.
4. Если пользователь говорит “не знаю”:
   - разбей вопрос на меньшие
   - предложи 2-3 варианта
   - если всё равно неизвестно, пометь как `[уточнить]`
5. Если пользователь говорит “хватит вопросов”, создай черновик и явно укажи открытые вопросы.

## Artifact Lifecycle

Каждый существенный результат должен стать локальным файлом:

- профиль и состояние — `профиль/`
- анализ — `анализ/`
- правила — `правила/`
- контент — `контент/`
- решения — `решения/`
- знания и повторяющиеся паттерны — `база/`
- роли и автоматизации — `агенты/` или `.agents/skills/`

Если пользователь не подтвердил финальную версию, сохраняй как черновик или с полем `status: черновик`.

## Handoff For Future Agents

После каждого крупного шага обновляй handoff-слой:

```text
база/индекс.md             # карта базы
база/открытые-вопросы.md   # что спросить дальше
база/паттерны.md           # что повторяется
агенты/README.md           # какие агенты/мини-скиллы есть
```

Пиши эти файлы так, чтобы новый агент мог открыть папку и понять:

- что это за бизнес
- что уже собрано
- какие решения приняты
- какие правила обязательны
- что делать следующим шагом

## Proactive Next Step

После каждого шага предложи один следующий шаг:

- после профиля: “Теперь можно сделать анализ аудитории или попробовать первый пост.”
- после анализа: “Теперь посты и КП могут учитывать персоны.”
- после 2-3 правок: “Оформить это как правило?”
- после повторяемого процесса: “Создать локального агента под этот процесс?”
- после нескольких артефактов: “Проверить консистентность базы?”
